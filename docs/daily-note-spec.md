# GTS 데일리노트(오늘의 활동) 자동화 기획서

> Cursor 작업용 기획서. 이 파일을 gts-platform 저장소의 `docs/` 폴더에 넣고 Cursor에게 "docs/daily-note-spec.md 기준으로 Phase 1부터 구현해줘"라고 요청한다.

---

## 0. 목적과 범위

- 매일 센터 수업이 끝나면 선생님이 올린 수업 사진을 **아이별로 자동 분류**하고, 아이마다 **"오늘의 활동" 데일리노트 초안**을 자동으로 만든다.
- 선생님은 초안을 **확인·수정한 뒤 발송 버튼**만 누른다. 사람이 확인하기 전에는 절대 발송되지 않는다.
- 대상: 직영 체육센터(한남센터, 삼성센터, 엘리트코어) 수업. 파견 기관은 이번 범위에서 제외.
- 데일리노트는 매일 쌓이는 가벼운 기록이다. 분기별 자세측정·FMP 등 정식 평가(기존 evaluations)와는 별개로 운영하고, 나중에 분기 리포트에서 참고 자료로만 연결한다.

## 1. 전체 흐름

```
[선생님] 수업 종료 → 구글드라이브 "내 폴더"에 사진 업로드 (폴더 정리 규칙 없음)
   ↓ (Google Drive 동기화)
[맥미니 사진 워커] 새 사진 감지 → 선생님 + 촬영 시간으로 수업(센터·반) 자동 판별
                 → 그 반 출석 아이들 명단만 가져옴 → 얼굴 인식 → 아이별 판정
   ↓ (전용 API로 업로드)
[gts-platform] 사진 저장 + 아이별 데일리노트 초안 생성 (사진 + 오늘의 활동 문구)
   ↓
[선생님 검토 화면] 반 단위로 확인 → 사진 빼기/배정 → 문구 수정 → "확인 후 발송"
   ↓
[발송] 카카오 알림톡 (아이 전용 링크) → 부모님이 링크에서 사진과 노트 확인
   ↓
[하메스] 매일 저녁 처리 현황 요약을 형님 텔레그램으로 보고
```

## 2. 역할 분담

| 구성요소 | 하는 일 | 하지 않는 일 |
|---|---|---|
| 선생님 | 내 폴더에 사진 업로드, 검토 화면에서 반 메모·아이별 체크 입력, 초안 검토, 발송 | 폴더 정리, 사진 분류 작업 |
| 맥미니 사진 워커 (Python) | 얼굴 인식, 판정, 플랫폼으로 사진 전송 | 문구 작성, 발송 |
| gts-platform | 노트 초안 생성, 검토 화면, 알림톡 발송, 부모 열람 페이지 | 얼굴 인식 |
| n8n | 워커 실행 스케줄, 실패 알림 | 판단이 필요한 일 |
| 하메스 | 일일 현황 요약·보고, 에러 전달 | 발송, 코드 수정, 데이터 수정 |

- **얼굴 데이터(특징값, 기준사진)는 맥미니 밖으로 나가지 않는다.** 플랫폼에는 "어떤 사진에 어떤 아이가 있다"는 결과만 전달한다.
- 기존에 설계했던 AWS Rekognition 방식은 이 구조로 대체한다. 기존 테이블(`class_photos`, `photo_tags`, `photo_send_log`)은 재사용하고, `student_faces`는 얼굴 데이터 대신 동의 상태만 관리하도록 바꾼다.

## 3. 구글드라이브 폴더 규칙

### 3-1. 구조
```
GTS수업사진/            ← 대표 계정 소유
  ├── 김OO선생님/        ← 해당 선생님에게만 업로드 권한
  ├── 이OO선생님/
  └── ...
```
- 선생님은 수업 후 **자기 폴더에 사진을 그냥 올리기만** 한다. 날짜·센터·반 폴더를 만들지 않는다.
- 어느 수업 사진인지는 워커가 **선생님 폴더 + 사진 촬영 시간**으로 판별한다(4-3 참고).
- 선생님 폴더와 플랫폼 선생님 계정의 연결은 플랫폼 `teachers` 테이블에 `drive_folder_name`(또는 드라이브 폴더 ID)을 저장해 관리한다.

### 3-2. 권한
- 폴더 소유자는 대표 계정. 선생님은 **자기 폴더에만** 편집(업로드) 권한을 준다. 상위 폴더 공유 금지(다른 반 사진 열람 방지).
- 선생님이 퇴사하면 해당 폴더 권한만 회수한다. 사진은 대표 계정에 그대로 남는다.
- 선생님 안내: "업로드 후 개인 폰 앨범에서 수업 사진 삭제".

### 3-3. 사진 형식
- 아이폰 원본(HEIC) 그대로 올려도 된다. 워커가 JPG로 변환한다.
- **카카오톡 등으로 전달받은 사진은 촬영 시간 정보가 지워져** 수업 판별이 안 된다. 선생님이 직접 찍은 원본을 올리도록 안내한다(해당 사진은 확인필요로 분류됨).

## 4. 맥미니 사진 워커

### 4-1. 폴더 구조 (`~/GTS업무/도구/사진분류/`)
- `config.yaml` : 드라이브 동기화 경로, 플랫폼 API 주소, 기준값(threshold), 수업 시간 여유폭, 실행 옵션
- 맥미니의 Google Drive 앱은 대표 계정으로 로그인하되, **`GTS수업사진` 폴더만 오프라인 동기화**로 설정한다. 회사의 다른 문서는 맥미니에 내려받지 않는다.
- `faces.db` : 아이별 얼굴 특징값 (SQLite, 맥미니 로컬 전용)
- `기준사진/<학생ID>/` : 아이별 정면 사진 3~5장
- `기록/인식기록.csv`, `기록/요약_YYYY-MM-DD.json`
- `확인필요/` : 로컬 확인용 복사본 (플랫폼 검토 화면에도 동일하게 표시)

### 4-2. 명령
- `register` : 플랫폼에서 **얼굴 인식 동의한 학생 명단**을 받아, 기준사진이 있는 학생만 특징값 생성. 동의 명단에 없는 폴더는 건너뛰고 경고.
- `run` : 새 사진 처리. 이미 처리한 사진(파일 해시 기준)은 건너뜀.
- `remove <학생ID>` : 특징값·기준사진 삭제 (퇴원·동의 철회 시).
- `sync-consent` : 플랫폼 동의 상태와 로컬 등록 상태를 비교해, 동의 철회된 학생을 자동 삭제.
- 공통 옵션 `--dry-run` : 업로드 없이 판정 결과만 출력.

### 4-3. 수업 판별 규칙 (어느 반 사진인가)
1. 사진이 들어온 **선생님 폴더**로 선생님을 알아낸다.
2. 사진의 **촬영 시간**(EXIF DateTimeOriginal, 한국 시간 기준)을 읽는다.
3. 플랫폼 API에 선생님 + 촬영 시간을 보내, 그 시간에 그 선생님이 진행한 수업(센터·반·수업ID)을 받는다.
   - 수업 인정 범위: 수업 시작 15분 전 ~ 수업 종료 30분 후 (config에서 조절)
4. 판별 결과별 처리:
   - 수업 1개 매칭 → 그 수업으로 확정
   - 매칭 없음(수업 외 시간) → "확인필요(수업 판별 불가)"
   - 촬영 시간 정보 없음(전달받은 사진, 스크린샷 등) → "확인필요(촬영시간 없음)"
   - 겹치는 수업 2개 이상 → "확인필요" + 후보 수업 기록
5. 추측으로 수업을 정하지 않는다.

### 4-4. 얼굴 판정 규칙 (사진 속 아이가 누구인가)
1. 수업이 확정된 사진만 얼굴 판정을 한다.
2. 플랫폼 API로 **그 수업 출석 학생 중 얼굴 인식 동의한 학생 명단**만 받아온다.
3. 사진의 모든 얼굴을 찾고, 명단 안의 학생과만 비교한다.
4. 유사도 기준 (config에서 조절):
   - 높음 → 해당 학생으로 확정
   - 중간 → "확인필요" + 후보 학생 최대 3명 기록
   - 낮음 또는 명단 밖 얼굴 → 무시하고 **특징값을 저장하지 않는다**
5. 한 사진에 여러 아이가 있으면 아이마다 각각 판정한다.

### 4-5. 플랫폼 전송
- 전용 API로만 전송한다. **맥미니에 Supabase service role key를 두지 않는다.**
- 장치 토큰(device token)을 발급해 `config.yaml`이 아닌 macOS 키체인에 저장한다. 이 토큰은 아래 API만 호출할 수 있다.
  - `GET /api/device/session?teacher=&taken_at=` : 선생님+촬영시간으로 수업 판별 (후보가 여럿이면 목록 반환)
  - `GET /api/device/roster?session_id=` : 그 수업의 출석+동의 학생 명단
  - `GET /api/device/consents` : 동의 상태 전체 목록 (학생ID, 동의여부, 갱신일)
  - `POST /api/device/photos` : 사진 파일 + 판정 결과(학생ID, 판정, 유사도, 후보) 업로드
- 사진은 업로드 전 긴 변 2048px로 줄이고, 위치정보(EXIF GPS)는 제거한다.

### 4-6. 필수 조건
- 원본 사진은 이동·수정·삭제하지 않는다.
- 모델 다운로드 이후 인터넷 통신은 플랫폼 API 호출만 허용한다.
- 얼굴 인식 모델은 **상업적 사용이 허용된 라이선스**로 고른다(비상업 전용 모델 금지). README에 모델명과 라이선스를 명시한다.
- Apple Silicon 가속 사용.
- 실행은 n8n이 10분마다 호출(수업 시간대인 13시~22시만). 한 번 실행이 끝나기 전에 중복 실행되지 않게 잠금 파일 사용.

## 5. gts-platform 변경

### 5-1. DB (Supabase 마이그레이션)
- `students`에 추가: `face_consent boolean default false`, `face_consent_at timestamptz`, `face_consent_revoked_at timestamptz`
- `teachers`에 추가: `drive_folder_name` (또는 `drive_folder_id`)
- `class_photos` (재사용/보완): `id, center_id, class_id, class_date, teacher_id, taken_at, session_match ('matched'|'no_session'|'no_exif'|'ambiguous'), storage_path, uploaded_by_device, file_hash unique, created_at`
- `photo_tags` (재사용/보완): `photo_id, student_id, status('confirmed'|'needs_review'|'rejected'), similarity, candidates jsonb, reviewed_by, reviewed_at`
- 신규 `daily_notes`:
  - `id, student_id, class_id, class_date, center_id, teacher_id`
  - `status ('draft'|'reviewed'|'sent'|'failed'|'skipped')`
  - `activity_text` (반 공통 오늘의 활동), `personal_text` (아이별 한 줄, 선택)
  - `ai_generated boolean`, `edited_by_teacher boolean`
  - `reviewed_at, sent_at, created_at, updated_at`
  - unique(student_id, class_id, class_date)
- 신규 `daily_note_photos`: `daily_note_id, photo_id, sort_order, included boolean default true`
- 신규 `daily_note_inputs`: `class_id, class_date, teacher_id, class_memo, student_checks jsonb` (선생님 입력 원본)
- `photo_send_log` (재사용): 발송 채널, 수신 번호(마스킹 저장), 결과 코드, 재시도 횟수
- RLS: teacher는 본인 담당 반의 노트·사진만 조회/수정. 부모 열람은 토큰 링크로만.

### 5-2. 노트 초안 생성
- 반의 첫 사진이 들어오고 **마지막 업로드 후 20분간 추가 사진이 없으면** 그 반 출석 학생 전원의 `daily_notes`(draft)를 만든다.
- 사진이 0장인 아이도 노트는 만들고 검토 화면에 "사진 없음"으로 표시한다(선생님이 사진을 직접 배정하거나 문구만 발송 가능).

### 5-3. "오늘의 활동" 문구 생성 규칙
- 기존 Claude API 리포트 생성 기능을 재사용한다. 얼굴 데이터·사진 파일은 AI에 보내지 않는다.
- 입력: 그날 수업 계획(월간 계획안의 해당 회차), 반 메모(검토 화면에서 선생님 입력), 아이별 체크 항목.
- 처음 초안은 수업 계획만으로 만들고, 선생님이 검토 화면에서 메모·체크를 입력한 뒤 **"문구 다시 만들기"**를 누르면 반영해서 다시 생성한다.
- **반 공통 문구(activity_text)**: 오늘 한 활동과 목적을 부모님 눈높이로 2~3문장.
- **아이별 한 줄(personal_text)**: 선생님이 입력한 체크 항목이 있을 때만 생성한다. 체크가 없으면 비워둔다.
- **아이의 행동이나 모습을 지어내지 않는다.** "OO이가 오늘 점프를 제일 잘했어요" 같은 개별 관찰은 선생님 입력에 근거가 있을 때만 쓴다.
- 신체·건강·발달에 대한 평가성 표현("발달이 늦다", "키가 클 것" 등)은 쓰지 않는다. 그런 내용은 분기 평가 리포트 영역이다.
- 말투: 따뜻한 존댓말, 이모지 최대 1개, 전체 300자 이내.
- 아이별 체크 항목 예시(선생님이 탭으로 선택): 적극 참여 / 새 동작 도전 / 친구 도와줌 / 오늘 조금 힘들어함 / 부상 없음 확인 / 특이사항 있음(자유입력)

### 5-4. 선생님 검토 화면
- 진입: gts-gear의 수업 종료 알림 → "데일리노트 검토" 버튼 → 플랫폼 검토 화면(해당 반, 해당 날짜).
- 화면 구성: 상단에 반 공통 문구(수정 가능), 아래 아이별 카드 목록.
- 아이별 카드: 사진 썸네일(빼기/순서 변경), 아이별 한 줄(수정 가능), 체크 항목, 상태 배지.
- "확인필요" 사진 영역: 사진마다 후보 아이 버튼(최대 3명) + "다른 아이" 선택 + "해당 없음". 여기서 배정한 결과는 `photo_tags`에 반영.
- "수업 판별 불가" 사진 영역: 선생님의 그날 수업 목록 중에서 선택하면, 그 수업으로 옮겨서 얼굴 판정을 다시 돌린다.
- 버튼: "이 아이 제외"(오늘 발송 안 함), "전체 확인 후 발송". 확인필요 사진이 남아 있으면 발송 전에 경고.
- 발송 후에는 수정 불가, 필요 시 "정정 발송"만 가능.

### 5-5. 발송
- 카카오 알림톡 템플릿(사전 승인 필요): "[GTS] OO이의 오늘의 활동이 도착했어요. 아래 버튼을 눌러 확인해주세요." + 링크 버튼.
- 링크: 아이별 1회성이 아닌 **만료형 토큰 링크**(7일). 페이지에서 사진은 서명 URL(짧은 만료)로 표시.
- 발송 가능 시간: 08:00~21:00. 21시 이후 확인한 건은 다음날 08:30 예약 발송.
- 실패 시 최대 3회 재시도, 최종 실패는 검토 화면과 관리자 대시보드에 표시.

### 5-6. 부모 열람 페이지
- 모바일 우선. 오늘의 활동 문구, 아이 사진, 날짜·센터·반.
- 사진 저장 버튼 제공. 다른 날 노트 목록은 Phase 3에서 추가.

## 6. 하메스 역할 (맥미니)
- 매일 21:30, 워커 요약 JSON과 플랫폼 현황 API(읽기 전용)를 읽어 형님 텔레그램으로 보고:
  - 처리 사진 수, 자동 확정 비율, 확인필요 수
  - 반별 검토/발송 완료 여부, 미발송 반 목록
  - 워커 에러
- 하메스는 발송·수정·삭제를 하지 않는다. 에러가 나면 내용을 그대로 전달하고 멈춘다.

## 7. 개인정보·안전 규칙
- 얼굴 인식 동의(`face_consent = true`)한 아이만 등록·판정한다. 미동의 아이의 얼굴은 특징값을 만들지 않는다.
- 동의 철회·퇴원 시: 플랫폼에서 상태 변경 → 워커 `sync-consent`가 맥미니 얼굴 데이터 자동 삭제 → 삭제 기록 남김.
- 데이터 보관 기간(예: 사진 1년)을 정하고 만료 데이터 자동 삭제 작업을 둔다. (기간은 결정 필요)
- 부모 열람 링크는 로그인 없이 열리므로 추측 불가능한 긴 토큰을 쓰고, 검색엔진 수집을 막는다(noindex).
- 관리자·선생님의 사진 열람·다운로드는 로그로 남긴다.

## 8. 분기 평가와의 연결 (나중)
- 분기 자세측정·FMP 리포트 생성 시, 해당 분기 데일리노트의 참여 기록(출석 횟수, 체크 항목 빈도, 대표 사진 몇 장)을 참고 자료로 붙인다.
- 데일리노트 문구를 평가 점수의 근거로 쓰지 않는다.

## 9. 구현 순서
- **Phase 1 (워커 단독 검증)**: 맥미니 워커 register/run/remove, `--dry-run`으로 실제 수업 사진 1주일 테스트. 이 단계에서는 수업 판별 API 대신 로컬 시간표 CSV로 대체해도 된다. 수업 판별 정확도와 얼굴 판정 정확도를 따로 기록하고 기준값 확정.
- **Phase 2 (플랫폼 연결)**: DB 마이그레이션, 장치 토큰과 device API, 노트 초안 생성, 검토 화면. 발송 없이 검토까지만.
- **Phase 3 (발송)**: 알림톡 템플릿 승인, 발송·재시도·예약, 부모 열람 페이지. 한 센터(엘리트코어)에서 먼저 2주 운영.
- **Phase 4 (확대·운영)**: 전 센터 적용, 선생님 폴더 생성·권한 관리 화면, 하메스 일일 보고, 보관기간 자동 삭제(드라이브 원본 포함), 분기 리포트 연결.
